# Experiment voice audio capture

`VoiceOptions.recordAudio` defaults to false. A caller that enables it supplies `onAudioSegment(segment)` and may supply `onRecordingStatus(status)`. The adapter captures its microphone's actual `MediaStreamTrack` as `user` audio and each subscribed remote audio track as `assistant` audio. It does not synthesize audio from captions or upload clips itself.

`VoiceAudioSegment` contains an opaque ID, direction, observed wall-clock `startedAt`/`endedAt`, a private `Blob`, actual MIME type, and byte count. The browser prefers WebM/Opus, then WebM/MP4, then its supported default. Each new recorder produces a separate clip; it rolls at 60 seconds and stops capture at a 30-minute session bound. Clips are capped at 16 MiB, with bounded simultaneous sources and pending delivery. Unsupported capture, browser errors, size limits and receiver errors produce explicit recording status errors.

Pause stops and flushes the current audio segments. Resume starts new clips, leaving a genuine recording gap. The recorder never closes SDK-owned tracks. Voice shutdown stops recorders immediately, releases SDK audio resources, and awaits final browser data events and segment-receiver promises before reporting `disconnected`. A closing experiment receiver must therefore remain available until shutdown resolves; it must not drop final segments merely because a UI operation counter changed.

These timestamps describe application capture windows. They do not establish sample-perfect synchronization between speakers, captions, video, or the simulated robot. MediaRecorder WebM often omits duration metadata; decoding the clip is a stronger format check than relying on a container duration field.

Seven unit checks cover asynchronous final flush, pause/resume, independent rolls, unsupported recording, bounds, browser/receiver errors and late-event cleanup. A separate no-provider Chrome check captures four actual encoded local-tone clips across pause/resume and independently decodes each with FFmpeg. Its evidence is under ignored `.local/qa/voice-audio-recorder-browser/`; it proves browser/codec integration, not a live microphone or provider recording. Reproduce with `node scripts/voice-audio-recorder-smoke.mjs`.

# Speech-to-command association

`onCommand(command, context?)` supplies `VoiceCommandContext` when invoked by the voice adapter. Direct recognized navigation, literal relative movement and Stop controls carry their exact provider caption, scoped turn ID, receipt time and `turnAssociation: exact-caption`. The later matching tool is deduplicated without another application command invocation.

Tool callbacks carry their command ID and the most recently observed user caption, if available, labelled `turnAssociation: latest-observed-user-turn`. The tool transport does not supply an authoritative LLM-to-ASR turn link. Consumers must preserve that distinction and must not silently treat this latest-caption context as proof of model turn alignment.

# Actual experiment rehearsal evidence

On 2026-11-21, one 40.444-second real Agora/Murf session used an explicitly labelled prerecorded microphone fixture. The application captured and uploaded separate actual microphone (80,357 bytes) and remote assistant (583,219 bytes) clips. Read-only verification downloaded each clip, matched its size and SHA-256 against the original application POST body, independently decoded both with FFmpeg, and played saved audio through the report's native player. The saved JSONL contains actual transcripts, native attempts, 194 world samples, requested-versus-observed evaluations and audio manifests. Native recorded replay advances actual stored frames. This is not a live human microphone or synchronized audio/video test.

The rehearsal also exposed a real model-action mismatch: ASR recognized “Please move forward one meter.” while the model executed `Go Home` with zero movement. The evaluator correctly marked the one-meter request failed. The next six-meter wording was initially unscored because its exact word form was outside the evaluator grammar. This failed rehearsal is retained unchanged under ignored `.local/qa/voice-experiment-live/`; it must not be presented as a passed task. Separate read-only export/audio/replay checks passed under its `saved-proof/` directory. The offline UI rehearsal separately proved Stop creates a draft, waits for asynchronous final audio, and saves only after the explicit Save choice; no provider or persistent-recording endpoint was called in that test.

Rehearsal scripts: `scripts/voice-experiment-workflow-smoke.mjs --offline` for intercepted UI checks; live mode additionally requires explicit `VOICE_EXPERIMENT_AUTHORIZED=yes` after session coordination. `scripts/voice-experiment-saved-proof.mjs` reopens existing evidence without starting voice. Actual provider sessions must be separately authorized; the scripts do not authorize themselves.

The follow-up speech gate now recognizes only final, literal relative movement requests (including numeric/word distances and narrow Hindi/Hinglish forms), preserves the amount, and delegates feasibility to the native controller. It rejects a later contradictory same-turn tool such as `Go Home`, deduplicates matching tools, and releases its guard on the next actual user turn. Exact failed ASR wording has been replayed through this gate and native engine: one meter reaches its actual point, six meters is refused by the native 0.05–5 m bound without motion. Thirteen pure speech/control checks and TypeScript passed. This is a source/unit verification of the fix; it is not a second live-provider success claim.

A later authorized corrected rehearsal passed all eight end-to-end checks: actual Agora start HTTP201, one 39.927-second session, native one-meter movement reaching `[-3, 1.5]` with one-meter measured travel, and a six-meter request refused by the controller's 0.05–5 m bound with zero travel. Its report deliberately contains one passed goal and one failed unmet goal; the refusal is not represented as a controller defect or successful six-meter movement. Stop produced an unsaved draft, the explicit Save choice created the experiment and two audio clips, and the QA console replayed real frames and played downloaded audio. The two native clips (79,400 and 565,194 bytes) matched their actual upload SHA-256/byte counts and decoded independently. The export contains 193 sampled world states alongside real transcripts, native attempt, evaluation rows and audio manifests. Evidence: ignored `.local/qa/voice-experiment-live-corrected-attempt2/`, experiment `1c042654-5568-4b71-9d02-b0ae67aa3198`.

The corrected-run MP4 contains captured screen frames plus those real separate audio clips; its filename and `video-audio-alignment.json` explicitly label approximate wall-clock alignment. It uses a prerecorded microphone fixture and does not verify a human microphone, acoustics, echo cancellation, hardware motion or sample synchronization. An intervening failed-start attempt is also preserved separately; it reached no RTC audio/captions and was never labelled a successful rehearsal. One remaining observed limitation is speech ordering: an early tool receipt can still describe initiation after a separate controller announcement has reported completion. Such historical receipt snapshots must not be treated as fresh status.
